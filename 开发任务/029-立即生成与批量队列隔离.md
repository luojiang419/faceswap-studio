## 验收与范围

- “立即生成”创建可见的队列任务并只执行该任务，自动显示生成队列；旧待办继续等待。
- “添加到队列”只创建待办；仅点击队列页“执行生成”才批量执行点击时的待办快照，执行中新增的外部任务不自动混入。
- 单次提交/批量执行互斥，失败、取消或完成后正确恢复。生成期间人脸上传、形象库加载、视频选择、清空及外部拖拽均锁定，跨页/旧轮询不提前解锁；后端拒绝绕过界面的素材修改。
- 检查真实安装版任务命令链路，使用隔离素材/任务验证，保护用户素材、现有队列和其他未提交改动。
- 必要 Python/Flutter 回归、analyze、Windows 构建与安装版运行验证通过，仅提交本任务文件。

## 实现与证据

- `run_workspace` 在队列锁内创建持久任务后只将新任务 ID 交给执行器，不再启动全部待办；`run_queue` 为显式批量入口，开始时固定待办列表。执行器不扫描吸收后来创建的外部任务，删除/取消的快照条目会跳过。
- 队列启动与创建互斥；线程启动失败会解除运行标记。单任务执行抛错也会将任务记为失败，执行器 finally 恢复运行标记，不影响取消和完成后的素材编辑。
- 工作台草稿响应提供 `generation_active`。两个标签页共享提交/生成状态和修订号，立即生成成功自动进入生成队列，提交中与生成中禁用素材按钮、形象库、清空、拖拽及生成按钮；旧轮询不提前解锁，失败、取消、完成后根据实际状态恢复。识别人脸和视频导入的原有并行能力继续保留。
- 后端源/目标设置、清空、形象库加载所用的源设置、识别入口和上传入口统一检查生成状态；生成时返回 HTTP 409，防止其他页面或旧请求绕过界面修改。识别结果提交时再次检查，避免在任务启动后覆盖素材。
