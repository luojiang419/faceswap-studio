## 恢复演示

在 Flutter 项目目录执行 `D:\flutter\bin\flutter.bat build web --release --no-pub --target tool/close_behavior_preview.dart --output G:\app\facefusion\faceswap-studio\build\close-behavior-preview\web --no-web-resources-cdn --no-wasm-dry-run`。

构建后把本机 `C:\Windows\Fonts\msyh.ttc` 复制到生成目录 `web/assets/preview-font/msyh.ttc`（仅本地演示，字体不进入 Git）。在生成的 web 目录运行仓库 Python：`python -m http.server 52749 --bind 127.0.0.1`，再打开上述地址。

Windows 下 Flutter 自定义输出目录须传绝对路径；相对输出路径会令 impellerc 无法写入 shaders。演示字体通过 rootBundle 载入；NetworkAssetBundle 使用 dart:io 的 HttpClient，不适用于 Web。

## 正式实现与验证

- `StudioWindowLifecycle` 挂在 MaterialApp 内，处理真实 Windows MethodChannel 关闭请求；同一时刻只显示一个弹窗，取消/Escape 不保存也不执行。
- `Win32Window.OnCloseRequested` 与 FlutterWindow 接通 WM_CLOSE；确认后执行原生退出或托盘隐藏。显式托盘退出与更新器退出保留强制关闭路由，避免被普通关闭确认拦截。
- Bridge 默认 `close_behavior=ask`，以 `close_behavior_configured=false` 区分首次询问与用户明确的“每次询问”；确认和设置保存后标记已配置。保留已有 exit/minimize_to_tray 偏好，不重置用户已保存的设置。
- 偏好先落盘再执行；写入失败时恢复内存中的关闭偏好，保持窗口打开并提示重试。Bridge 不可用时仍显示关闭选项，保存失败后可明确点击“仅本次关闭/仅本次转入后台”，不把未保存的选择冒充为已记住。
- 设置页新增“关闭软件 / 后台运行 / 每次询问”，保存立即生效；窄窗口支持横向滚动。
- Flutter 测试验证重复关闭、取消、保存/恢复、两种关闭动作、每次询问和失败重试。Python 验证真实磁盘读写、兼容旧值及写入失败回滚。
- `integration_test/close_behavior_windows_test.dart` 实际构建并运行 Windows 程序，确认测试窗口属于自身 PID 后发送 WM_CLOSE，验证弹窗、取消、原生托盘隐藏/恢复、再次直接隐藏和每次询问。该测试的 Bridge 为隔离内存夹具；真实磁盘持久化由 Python 测试独立验证。
- 修复同一后端回归文件中已有的测试夹具依赖：外网标签路由使用固定模型标签，不再随着真实魔搭镜像补齐而失效；没有更改模型下载实现。
- 原有 main.cpp、win32_window.cpp、配置及安装链路修改保留；对混有既有改动的文件仅暂存本任务差异。
