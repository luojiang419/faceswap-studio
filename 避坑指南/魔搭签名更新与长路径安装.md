# 魔搭签名更新与长路径安装

2026-10-18 在真实中文目录安装和线上更新中验证。

- **下载提前结束**：流式 `read(chunk)` 遇到 EOF 不保证已收到签名清单声明的大小。一次实测只收到 4 MiB；不能将短文件当作哈希损坏后删除。保留分片，从实际写入位置续接，核对 Content-Range 的起点与总大小，无进展时有限失败，完整后才校验 SHA-256。Python 截断 HTTP、原生截断/分段 CDN 测试及真实魔搭升级通过。
- **更新器被 Bridge 清理**：Windows 的新进程组不等于脱离 psutil 递归子进程树。使用一个短生命周期父进程启动独立更新窗口，父进程退出后再交还 UI；验证工作台与 Bridge 清理后更新器仍能完成事务。
- **深层 Python 依赖路径**：.NET Framework 默认兼容旧目标框架，仍可能走 260 字符限制。仅在首次路径访问之后设置 AppContext 开关无效，因为兼容开关可能已经缓存。安装器声明 TargetFramework 4.8、嵌入 longPathAware 清单，并在 Core 初始化时关闭旧路径处理；实际在深层中文测试目录解压 29599 项文件、启动和卸载通过。
- **源码内的同名目录**：Bridge 的 `models` 是 Python 模块，Flutter 的 `data` 是程序资源。更新白名单应按完整程序前缀定义，保护 `faceswap studio/data`、`faceswap studio/config`、`.assets` 和虚拟环境，不能递归禁止所有名字叫 models/data 的目录。
- **ZIP 显式目录条目**：7z 更新 ZIP 会记录目录。允许签名文件清单所需的父目录和根目录，拒绝额外目录、链接与越界；文件仍逐项验证大小与哈希。

证据：`build/installation-validation/installation-result.json`、`online-update-result.json`、`uninstall-result.json`；自动化测试位于 `tests/test_modelscope_client.py`、`tests/test_signed_updater.py` 和 `installer/bootstrap/Tests.cs`。

2026-10-19 模型来源混合分发补充验证：

- **魔搭普通文本换行**：Windows `write_text`生成CRLF，魔搭普通文本入库会转为LF，导致本地624367字节与远端611956字节不同，但JSON语义一致。发布前生成LF规范化副本，保留客户端原文件，按规范化副本SHA/大小匿名完整回读。`test_catalog_publication_normalizes_text_without_changing_client_catalog`与`catalog-publication.json`验证通过。
- **魔搭 JSON 分段返回 200**：2026-10-19 发布清单快照时，`Range: bytes=0-0` 实际收到 `200`、`Content-Length: 1` 和正确的 `Content-Range: bytes 0-0/612004`。不能只按状态码将200当作完整文件响应；若200/206携带Content-Range，须精确核对请求范围与清单总大小，仍只读取一个字节。没有范围头的200继续核对完整Content-Length，缺头的206及错误范围继续拒绝。`test_lightweight_refresh.py`覆盖三种合法响应与200/206错误总大小；真实清单快照、别名完整SHA回读通过。
- **国内模式阻止外网模型代理**：全局`NO_PROXY=*`会让显式ProxyHandler也绕过系统代理。国内模型使用空代理opener直连；环境仅排除localhost等本机地址，外网模型单独读取环境/Windows系统代理。真实HTTP代理转发、SHA验证和Bridge环境测试通过，不修改系统代理配置。
- **镜像与来源覆盖分开**：混合清单必须明确区分`download_origin=modelscope/external`。只有匹配已有匿名校验证明的条目才标为魔搭，其余保留上游固定提交及SHA/大小，禁止把“全部模型可按需下载”报告为“全部模型已镜像”。

2026-10-19 新版启动安装器验收补充：

- **验收 EXE 也必须声明长路径**：正式安装器编译已嵌入 `installer/bootstrap/app.manifest`；手工编译 InstallationSmoke 时漏掉 `/win32manifest`，依然可能在深层 Gradio 字体路径报 DirectoryNotFoundException。仅有 .NET 4.8 属性及 AppContext 开关不够。测试程序使用与正式安装器相同的清单后，长中文目录完整展开及真实启动通过。
- **Python 隔离不绕过 Flutter 原生单实例锁**：`FACESWAP_STUDIO_ISOLATED=1` 只隔离 Python 启动器，当前原生窗口仍使用全局单实例 mutex。已有窗口运行时，新安装前端会立即正常返回 0，导致安装握手失败。先确认队列为空，再用现有退出入口正常关闭原工作台；在 finally 中停止所属隔离测试进程并恢复原工作台。不可将返回 0 当成新窗口启动成功。`build/installer-face-fusion/original-restored.json` 与 `install-verified/installation-result.json` 验证恢复及新安装核心 ready。
- **打包新的前端无需覆盖当前部署**：`build_lightweight.py --windows-build-root <Release目录>` 按正式安装路径映射新构建，排除 PDB 并检查必要文件。新运行包内实际 app.so 等文件与新构建 SHA 一致，本机部署目录保持原状；对应真实文件路由回归通过。

2026-10-19 新基准与旧版过渡补充验证：

- **更名后的新路径被旧客户端拒绝**：旧 0.1.3 事务只允许原启动文件名，直接发布仅含“易容 Studio.exe”的更新会在旧白名单处失败。首次过渡包使用 `--legacy-entry`，保持旧客户端接受的路径；事务确认完成后由新启动器整理标准入口，之后即可接受新标准包。真实旧发布代码的手动升级及后续新入口更新均通过。
- **升级归属记录必须同步**：只替换应用文件会遗漏新入口、快捷方式及卸载维护程序。安装身份与新增文件在事务确认完成后整理；校验签名、SHA-256、归属和注册路径，保护其他应用同名快捷方式。中途退出后下次启动继续整理，不重新安装。原生修复同样合并文件归属并备份原身份。
- **旧卸载器不认识新入口**：过渡签名清单绑定当前基准安装器的 URL、大小和 SHA-256；新启动器在更新确认后校验并更新卸载维护程序，避免旧卸载器留下新快捷方式和新文件。坏维护程序拒绝替换；原程序备份保留。
- **无需重复下载大包验收上传**：默认发布使用远端 SHA-256、大小与匿名单字节访问，完整回读仅显式执行。新装及旧版两次升级使用已验证本地完整缓存和本机 HTTP 服务，正式安装器另做小文件真实 HTTPS 续传；公开元数据再分别由新、旧客户端验证。

证据：`开发任务/018-最新基准安装包与旧版更新衔接.md`、`build/baseline-release/` 和基准输出目录的 `verification.json`。
