# 全量包目录条目与隔离验收

## 7z 增量 ZIP 的目录条目

表现：全量资源由 Python 首次生成时校验正常，使用 7z 增量替换应用后，文件数量校验报“资源包文件集合不一致”。

根因：7z 会补写目录条目，`ZipFile.infolist()` 同时包含文件与目录。签名资源清单只记录文件，不能直接与全部条目数量比较。

解决：数量比较与逐文件 SHA-256 校验使用 `not entry.is_dir()` 的集合，保留根目录校验及每个文件的大小/SHA 验证。原生展开仍检查目录是否属于清单父路径，不能用目录过滤放松解压边界。

验证：`tests/test_full_offline.py::test_distribution_verifies_real_files_with_explicit_zip_directories`；2026-10-24 实际全量包包含 21,817 个文件，并通过内层完整逐文件 SHA、外层 ZIP CRC 校验。

## 原生隔离验收必须对齐生产配置

- 引用 .NET 4.8 安装器的独立 C# 验收程序，也需声明 `.NETFramework,Version=v4.8` 并在首次路径访问前禁用 legacy path handling。未声明时，测试 EXE 默认兼容旧框架，在深层中文目录先触发 260 字符限制，不能据此误判正式安装器故障。
- 安装就绪握手的 session 必须是 GUID `N` 格式（32 位十六进制），不能临时使用 `offline-smoke` 之类名称。就绪报告应来自真实桌面 `/updates/healthy` 回调，验收工具不能手工伪造。
- `dict(os.environ)` 是普通 Python 字典，丢失 Windows 环境对象的大小写不敏感行为。取 Windows 系统目录用 `os.environ.get('SystemRoot')`，不能假设复制后的字典保留 `SystemRoot` 而不是 `SYSTEMROOT`。
- Python 的隔离服务锁与 Windows runner 的单实例锁必须同时区分测试安装。现有 `FACESWAP_STUDIO_ISOLATED=1` 在 runner 中按可执行文件路径追加实例标识，正常启动保持原有单例行为。实际验收确认正式工作台与隔离工作台同时存活，隔离进程只连接专用端口。

验证：`scripts/verify_full_offline.py` 的实际中文路径安装、真实首帧凭证、核心 ready、GPU 卷积与原版 WebUI 下载；`installer/bootstrap/OfflineSmoke.cs` 使用专用测试注册项和内部快捷方式。

## 使用正确的已构建前端与 Flutter SDK

工作区 `runtime/windows_app/current` 可能早于正式安装目录中的人工验证版本。全量打包默认取指定安装目录前端，或显式指定最新完整 Release；以 `data/app.so` SHA 验证，不只看目录名称。

Windows 集成测试可能将 CMake 的 Flutter target 留在临时 listener.dart。直接 `cmake --build` 会寻找已清理的测试入口；使用正确 SDK 的 `flutter build windows --release --no-pub --target lib/main.dart` 重建。本机 `D:/flutter` 与当前 package_config 匹配；误用项目 `.tools/flutter` 会出现框架/engine API 不匹配（`hitTestTransform`）。本次改用 `D:/flutter/bin/flutter.bat` 后 Release 构建通过，`app.so` 与已验证正式前端 SHA 一致。
