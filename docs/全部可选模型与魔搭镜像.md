# 全部可选模型与魔搭镜像

当前源码清单已覆盖全部模型的按需下载链路：97 个 ONNX 权重全部走魔搭；剩余 74 个人物 DFM 按用户要求保留原仓库固定地址，选择时才自动补齐，标记“外网下载”并检测系统代理。无需下载或转存全部人物模型。

2026-10-19 先检查了魔搭以外的来源，详见[国内模型镜像检查报告](国内模型镜像检查-2026-10-19.md)。随后按用户最终选择，仅将 `ddcolor_artistic.onnx`、`deoldify_stable.onnx`（合计约 1.73 GiB）补传魔搭，两个权重均完成本地 SHA-256/CRC、服务端元数据、匿名完整 SHA-256 回读及首尾比对。完整来源清单及其固定快照也已发布并匿名完整回读；本轮没有重新构建或发布应用更新、安装包，既有安装版需后续应用更新带入新清单。

## 覆盖范围

按 FaceFusion 3.9.0 源码的全部 `create_static_model_set('full')` 枚举，共 247 个内置模型选项，包含 97 个 ONNX 权重、157 个 DeepFaceLive DFM 权重，以及对应的 254 个 hash 文件，共 508 项资产、约 168.75 GiB。当前核心已升级到 3.9.1，该补丁版没有新增模型或改动资产定义，继续复用已验证的 `models/facefusion-3.9.0-v1` 固定清单与资源地址。

覆盖检测、属性、关键点、遮罩、识别、内容分析、声音分离、年龄修改、背景移除、表情恢复、人脸编辑/增强/换脸、画面上色/增强、口型同步及内置 DeepFaceLive 模型。用户自行导入的 `custom` 私有模型不上传；演示图片、音频和视频不属于此模型清单。

当前清单中 434 项已验证魔搭镜像，约 78.21 GiB；74 项 DFM 权重使用固定上游地址，约 90.54 GiB。所有 97 个 ONNX 和 254 个 hash 文件均已镜像；其余已镜像的 83 个 DFM 保持原状。每项保留上游仓库、固定提交、LFS SHA-256、原始 CRC、原模型选项及其许可元数据。权重沿用各自上游许可，不能把模型仓库中的全部内容理解为 Apache 授权。

默认常用集合仍为 14 个 ONNX 加对应 hash，约 1.68 GiB，已随安装包提供；镜像库总量不代表安装容量或普通换脸的必需下载量。

## 使用方式

完整清单随签名应用更新分发，存放在 `facefusion/model_catalog.json`。选择缺失模型时才从魔搭下载；现有有效模型校验复用，首次安装继续只包含默认常用模型。

工作台启动的服务、预览和队列优先使用魔搭。工作台模型选择框和补齐日志会标记外网模型，并提示自动使用系统代理。外网模型从Hugging Face原始固定提交下载；系统代理通过环境变量与Windows代理设置动态读取，不猜测端口。没有系统代理时尝试直连，失败保留分片并报告。自定义代理模式仍优先使用用户填写的代理。魔搭直连模式仅让国内模型直连，不会阻止外网模型单独读取系统代理。

独立 CLI 可通过 `--download-providers modelscope` 使用同一来源清单，也保留显式选择 `github`、`huggingface` 的兼容能力。

下载使用固定大小和 SHA-256，支持断点、分段 CDN、截断恢复和空间预检；临时文件验证通过后原子替换。模型的原始 CRC 继续验证，采用分块读取，避免 DFM 预检一次性读入整个大文件。

## 维护与恢复

```powershell
# 使用已有逐项证明生成混合来源清单，无证明的权重明确标为外网下载。
python scripts/modelscope_models.py route-catalog
# 审计来源路由，不要求全部DFM镜像。
python scripts/modelscope_models.py audit
```

当前目标已完成，不再运行全量 `publish` 补齐那 74 个 DFM。此次定向转存与发布证明位于 `build/modelscope-two-onnx/`；先发布不可变清单快照，再确认旧清单 SHA 未变化后更新 `catalog.json` 别名，并完整匿名回读。不可用通用不可变资源上传器直接覆盖同名不同内容文件。

维护目录为 `build/modelscope-all-models`，不提交模型二进制或登录凭据：

- `plan.json`：来源、固定哈希、大小与目标路径。
- `proofs/*.json`：每项已完成的可恢复证明。
- `progress.json`：当前完成数量、容量及错误计数。
- `publication.json`：全量镜像状态与本轮请求范围；`complete=false` 表示尚未镜像全部 DFM，`requestedComplete=true` 表示本轮两个 ONNX 已完成。
- `cache`：每个工作线程一个权重缓存；成功转存并核验后只清理本次生成的缓存文件，原 `.assets/models` 不删除。

脚本通过魔搭 SDK 确认全局已存在的相同 SHA 对象并复用其 LFS 引用，缺失对象才从上游下载、完整校验后上传。传输并行，仓库提交串行，避免提交锁冲突。恢复时优先处理已有缓存和已验证条目。

混合来源发布门禁比对当前源码、完整计划、现有镜像证明和固定上游元数据。只有具备匹配匿名回读证明的资产才标记魔搭；其他项必须明确标记外网下载，保留原始SHA/大小。审计通过代表全量模型有明确下载路由，不代表全部权重已镜像，也不代表已逐项推理。签名更新与新安装运行包包含同一份清单。安装器可用 `scripts/build_lightweight.py --output <新目录> --refresh-from <已验证旧运行包>` 复用已有依赖；旧产物保留，新文件写入后逐项检查SHA-256。

所有 hash 文件完整匿名回读；权重校验上游 SHA/CRC、本地完整文件、服务端 SHA/大小及匿名首尾范围。客户端实际下载时再次验证整个权重 SHA-256。此审计不等同于逐个模型都执行了推理。
